# Миграция «Зооконсьерж» на российскую инфраструктуру

Статус: подготовка к переносу. Production на Railway пока не отключать и базу не удалять.

## 1. Как устроен проект

- zoobot — основной production backend: Telegram-бот, веб-сайт, заявки, чат, портал администратора и база SQLite.
- zoosite — отдельная React/TypeScript версия сайта. Пока не переключать домен на неё: текущий адрес zk-pomosh.up.railway.app обслуживается веб-сервером из zoobot.
- bot.py запускает polling Telegram и сайт в одном процессе. На хостинге нужен один постоянно работающий контейнер.
- База задаётся через DB_PATH. Для Amvera она должна быть /data/zoobot.db.

## 2. Почему рассматривается Amvera

В официальной документации Amvera есть Docker deployment, постоянный том /data для SQLite и бесплатный HTTPS-домен amvera.tech. На официальной странице провайдер также пишет, что обращения приложений к Telegram API автоматически идут через иностранный IP. Это может помочь связи сервера с Bot API, но не гарантирует доступность самого Telegram у клиентов в каждой сети РФ.

Для хранения данных в РФ предусмотрены регионы Москва_0 и Москва_1. В договоре обработки персональных данных Amvera указано, что в этих регионах данные, логи и резервные копии остаются в России. При создании приложения обязательно выбрать один из этих регионов, а не оставлять выбор по умолчанию.

### Стоимость на момент подготовки документа

- Пробный: 0,1 CPU, 100 МБ RAM, 2 ГБ SSD — 0,24 ₽/час, примерно 170 ₽ за 30 дней.
- Начальный: 0,25 CPU, 500 МБ RAM, 5 ГБ SSD — 0,40 ₽/час, примерно 290 ₽ за 30 дней.
- Начальный Плюс: 0,5 CPU, 1 ГБ RAM, 7 ГБ SSD — 0,68 ₽/час, примерно 490 ₽ за 30 дней.
- Стартовый баланс 111 ₽ начисляется после регистрации. Это тестовый кредит, а не бесплатный постоянный хостинг.
- Встроенные бэкапы /data доступны с тарифа Начальный Плюс и выше; сервис хранит бэкапы за последние два дня. Нужна также собственная периодическая копия вне приложения.

Для короткой проверки можно начать со стартового баланса. Но 100 МБ RAM — только экспериментальный минимум: бот, веб-сайт, планировщик и криптографические библиотеки работают в одном процессе. Документация Amvera советует при первой сборке взять тариф с большим запасом и затем снизить его по фактическому потреблению. Для первого запуска разумно проверить Начальный Плюс (1 ГБ RAM), затем при успешном замере попробовать Начальный (500 МБ RAM). Начальный Плюс также включает панельные бэкапы.

## 4. Что задать в Amvera

После создания приложения — открыть защищённые «Переменные / Secrets» и задать:

Обязательно:
- BOT_TOKEN — текущий production токен @zooconcierge_bot.
- ADMIN_IDS — Telegram ID администратора.
- DB_PATH=/data/zoobot.db.
- WEBAPP_URL — HTTPS адрес приложения Amvera на этапе проверки, затем адрес собственного домена.
- TIMEZONE=Europe/Moscow.

Дополнительные значения, переносить только если они используются:
- Данные оператора и политика: OPERATOR_NAME, OPERATOR_INN, OPERATOR_CONTACT, POLICY_URL.
- Яндекс ID: YANDEX_CLIENT_ID, YANDEX_CLIENT_SECRET.
- Почта: ADMIN_EMAIL и либо RESEND_API_KEY / RESEND_FROM, либо SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD, SMTP_FROM.
- Оплата: PAY_SBP_PHONE, PAY_SBP_BANK, PAY_CARD, PAY_RECIPIENT.
- Заявки внешнего сайта: SITE_LEADS_KEY, HELPER_NOTIFY_URL.
- Контакты и SEO: ADMIN_PHONE, YANDEX_VERIFICATION, GOOGLE_VERIFICATION, BING_VERIFICATION.

Реальные токены и пароли не передавать в чат и не сохранять в GitHub. В репозиторий добавляются только пустые шаблоны.

## 5. Безопасный порядок переключения

1. Создать приложение в Amvera и выбрать регион Москва_0 или Москва_1.
2. Развернуть код с тестовым токеном и отдельной тестовой базой. Проверить сборку и журналы приложения.
3. Проверить сайт: /healthz, /, /request, /contact, /policy, /chat, /portal.
4. Проверить доступность нового адреса с мобильного интернета нескольких российских операторов. Не считать проверку из одной сети гарантией.
5. После выкладки этой подготовительной версии на старую площадку открыть в админ-портале «Отчёты и база» (`/portal/reports`) и скачать «Полную копию SQLite». Новый защищённый пункт использует SQLite Backup API и проверяет целостность файла. Файл содержит персональные данные, пароли сессий и ключи: хранить только на доверенном устройстве, никому не пересылать. До появления этой кнопки на старом Railway можно сделать резервную копию через файловый доступ к volume, остановив приложение и скопировав БД корректно. GitHub хранит код, не рабочую базу.
6. Остановить старый production-процесс Telegram-бота, чтобы два процесса не использовали один BOT_TOKEN одновременно.
7. В приложении Amvera открыть раздел Data и загрузить проверенный SQLite-файл с именем `zoobot.db` в постоянное хранилище `/data`.
8. Внести production-переменные, обновить WEBAPP_URL и только после этого запустить production-бота.
9. Проверить новую заявку от начала до конца: создание записи, уведомление, отображение в портале, изменение статуса, оплата, клиентский чат, исполнительский поток, отчёты, push.
10. Перед финальной регистрацией админских Passkeys выбрать постоянный адрес сайта: Face ID / WebAuthn привязан к домену, поэтому после смены домена администратору потребуется войти через Telegram или подтверждённую почту и заново включить Face ID. Клиентские cookie-сессии и push-подписки тоже привязаны к старому домену — на новом адресе пользователям может потребоваться повторный вход и повторное включение push. Яндекс OAuth: в настройках приложения добавить новый callback `WEBAPP_URL/verify/yandex/cb`.
11. После успешной проверки подключить собственный домен и TLS, обновить WEBAPP_URL, ссылки и SEO. Если сначала тестировать на домене amvera.tech, не регистрировать Passkeys на нём до выбора финального адреса.
11. Сохранить Railway доступным для отката, пока новая система не поработает стабильно и не будет проверено восстановление из копии.

Не запускать второй экземпляр production бота с тем же токеном во время проверки: Telegram polling может конфликтовать.

## 6. Ограничения, которые нельзя решить одним переносом

- Telegram остаётся внешним сервисом. Российский сервер не может гарантировать, что само приложение Telegram и api.telegram.org доступны в каждой сети РФ. Поэтому на сайте должна оставаться самостоятельная форма /request, не требующая Telegram.
- Для резервного канала можно рассмотреть MAX. У MAX есть официальный Bot API и webhooks, но создать бота можно только после верификации профиля организации, ИП или самозанятого на платформе партнёров. Это отдельный этап, не подмена текущего Telegram-бота.
- Карта в webapp/index.html сейчас использует тайлы OpenStreetMap, Photon и Nominatim. Их доступность в РФ надо проверить отдельно. Переезд сервера не переносит картографические сервисы на российские серверы.
- Проверка телефона использует Яндекс OAuth.
- Почта может работать через Resend или SMTP; для персональных данных нужно отдельно проверить местонахождение и условия обработки почтового провайдера.
- Push на устройства зависит от инфраструктуры браузера Apple/Google/Mozilla. Это дополнительный канал, не основной.
- Для Яндекс Карт API нужен ключ; бесплатное использование имеет ограничения по типу продукта и хранению полученных данных. Не заменять карту на Яндекс API без проверки условий лицензии и сценария хранения адресов/координат.

## 7. Персональные данные и политика

Выбор российского региона хостинга — только часть 152-ФЗ. Нужно также проверить внешние передачи через Telegram, карту/геокодер, почту и push. После выбора фактического региона и домена обновить раздел 5.4 policy.py: назвать реального хостинг-провайдера, регион основной базы и условия хранения резервных копий. Политику и согласие на обработку персональных данных должен проверить специалист по 152-ФЗ до запуска для клиентов.
